# TSan 性能影响分析

> 结论先行：**TSan 是编译期插桩**——"切换 TSan/非 TSan"只能靠**重启进程换用另一变体的二进制**；**每个进程都开 TSan 会让服务器 CPU 迅速饱和**，正确姿势是总控按需、针对性地只给某几个组件开 TSan。**suppression 只降低报告噪音，不降低性能开销。**

## 1. TSan 如何工作（为什么贵）

ThreadSanitizer 通过编译期插桩，为每个加载、存储和同步原语维护**影子内存（shadow memory）**与**向量时钟**，在运行时做 **happens-before** 推演来判定数据竞争。付出两层代价：

- **影子内存**：每访问一块应用内存，都要读写对应的 shadow 槽位 → CPU 指令数成倍增加。
- **时钟/同步拦截**：每次 `pthread_*`、`std::mutex` 等同步都要插桩推进时钟 → 同步密集代码尤其昂贵。
- **巨大虚拟地址空间预留**：TSan 为 shadow 映射预留超大地址空间（典型可达数十 GB），受 `ulimit -v` 或容器内存硬上限约束时**启动即报错**。

## 2. 量级数据

| 指标 | 典型开销 | 说明 |
|---|---|---|
| 运行时（墙钟/CPU） | **5–15 倍** | 负载越重、同步越密集，越接近 15 倍；纯计算也可能低至 5 倍 |
| 内存（RSS） | **5–10 倍** | shadow 内存 + 运行时数据结构 |
| 虚拟地址空间 | 大幅上升 | 与容器/`ulimit -v` 冲突的风险点 |
| 二进制体积 | ~2–4 倍 | 插桩指令 |

> 本仓库提供实测基准：`./build/bin/bench_threads --threads 8 --seconds 5` vs `./build-tsan/bin/bench_threads ...`。同一负载下应观察到数量级差距（见 `bench/benchmark.md`）。

## 3. 如果"每个进程都开 TSan"，对服务器的影响

把整台服务器的组件全部换成 TSan 变体，后果是叠加的：

1. **CPU 饱和**：总负载放大 5–15 倍 → 同样吞吐所需的核数成倍增加，容量规划直接失衡。
2. **时延/吞吐劣化**：每个请求路径都变慢；对延迟敏感的服务（在线 RPC、实时逻辑）会明显劣化。
3. **内存压力与 OOM**：RSS 放大 5–10 倍，叠加 shadow 的高虚拟地址占用，线上实例易触发 OOM 或内存配额限制。
4. **调度与时序被扰动**：插桩改变了锁获取/线程调度的时序，可能**掩盖真实的竞态**，也可能**制造时序变化**——与生产行为不完全等价，反而干扰排查。
5. **全量排查噪音放大**：全量开启会让所有进程的报告一起涌出，真信号淹没在噪音里。

**因此不建议全量开启。** TSan 的定位是**正确性测试/排查工具**，不是常驻运行模式。生产或大规模环境里用"总控按需切换"模式：只对**正在排查的某个组件/某部分实例**临时开启 TSan，拿到结果后切回普通变体（正是本工程的作用）。

## 4. 缓解与规避策略

| 手段 | 作用 | 注意 |
|---|---|---|
| **只开子集** | 减少整体开销 | 总控按组件切换，另见 `docs/controller-guide.md` |
| **dev/CI 专用** | 正确性回归 | CI 里跑 TSan 变体的测试（本工程的 `build-tsan` + `ctest`） |
| **suppression（抑制文件）** | 只**降报告噪音**，**不降开销** | 用于屏蔽已知/误报，见 `tsan/tsan.supp` |
| **halt_on_error=0** | 服务进程遇首个竞态不退出 | TSan 默认遇到竞态直接退出，服务场景必须关掉 |
| **放宽虚拟内存上限** | 避免启动失败 | `ulimit -v unlimited`；不要给 TSan 实例设过紧的 RSS 上限 |
| **优化级别 -O1** | 竞态更可复现 | `-O1 -g`（本工程 TSan build type）比 `-O3` 更容易暴露竞态 |

## 5. 平台差异

- **Linux（一级验证基准）**：gcc / clang 的 TSan runtime 成熟稳定；`LD_LIBRARY_PATH` 注入变体库目录标准可用。
- **macOS**：Apple clang 与 brew clang 的 TSan runtime 稳定性差（误报、偶发 crash、启动受限），**仅作为开发冒烟**，结果以 Linux 为准。
